# Security audit — 2026-11-15

Scope: whole repo at commit 0727021 (local main, includes the unpushed iOS-backend merge). Read-only code review; nothing was run against production.

## High

- **F1. Admin password-reset OTP can be brute-forced; no rate limit.** `apps/api/src/admin/admin-auth.controller.ts:70-85`, `apps/api/src/admin/admin-auth.service.ts:154-209`. Anyone who knows a staff phone number can call `forgot-password/send-otp` without limit (each call creates a fresh 6-digit OTP), then try 3 codes per OTP on `forgot-password/verify-otp`, and repeat until a code matches. The reset token they get sets a new password, which means admin takeover and access to all customer data. The same endpoint also allows unlimited SMS bombing of staff phones and unlimited SMS cost. Fix: rate-limit send-otp per phone and per IP (`clientIp()`), as customer `send-otp` does. Rate-limit verify-otp per phone. Cap failed verifications per phone per day and lock the reset flow after that. Invalidate older unverified OTPs when a new one is issued.

- **F2. One anonymous request can freeze the API (CPU DoS).** `apps/api/src/products/products.service.ts:12-18` (`parsePeriod`) and `:217-229` (`availableStockForPeriod`). `GET /api/products?start_date=1970-01-01&end_date=9999-12-31` loops once per day (about 2.9M days) over every overlapping reservation, synchronously, which blocks the Node event loop. With real orders in the DB, a single request makes the whole API stop responding for minutes. Repeated requests keep it down. Fix: reject ranges longer than `MAX_RENTAL_DAYS` (90) and start dates in the past, as order creation does. Return 400 on bad dates.

- **F3. Anyone can reserve the whole inventory for free.** `apps/api/src/orders/orders.service.ts:70-171` (status `'CONFIRMED'` at line 134). Signing up only needs an OTP. A new account can create unlimited orders that are CONFIRMED immediately, unpaid, up to 10,000 units × 90 days each. The stock check then shows every product as sold out to real customers, on the website and in the iOS app. Fix (needs an owner/client decision): create orders as PENDING/unconfirmed until paid or approved by staff, and/or cap open unpaid orders per user (for example, 3). Add a per-user rate limit on `POST /orders` and an expiry for unpaid holds.

## Medium

- **F4. The OTP rate limits can be bypassed.** `apps/api/src/auth/auth.controller.ts:17` takes the raw `X-Forwarded-For` header (forgeable) as the IP. The project already has a safe helper, `common/client-ip.ts`. Phone numbers are also never validated or normalized (`auth.service.ts:20,49`), so `+998901234567`, `998901234567` and `998 90 123 45 67` are separate rate-limit keys that all reach the same phone. Result: unlimited SMS bombing of any number, SMS cost abuse, and duplicate user accounts for one phone. Fix: use `clientIp(req)`. Validate and normalize the phone (`^998\d{9}$`) before rate limiting, OTP storage and user lookup, in both the customer and admin flows. Check prod for existing duplicate users.

- **F5. One storefront XSS gives full account takeover, and also reaches the admin API.** The customer's 30-day bearer token is kept in localStorage and in a JS-set cookie with no `Secure`/`HttpOnly` (`apps/web/src/stores/auth-store.ts:27-39`). There is no CSP on web or admin. API CORS (`apps/api/src/main.ts:15-25`) allows the storefront origins with `credentials: true` on every route, including `/api/admin/*`. The admin cookie is `SameSite=Lax`, and rentevent.uz and admin.rentevent.uz count as the same site. So script running on rentevent.uz in a logged-in staff member's browser can call admin endpoints and read the responses. Fix: allow only `https://admin.rentevent.uz` for `/api/admin/*` (separate CORS check or a middleware). Add a CSP to web and admin. Add `Secure` to the `auth-token` cookie. Longer term, move the customer token to an HttpOnly cookie set by the API.

- **F6. The Multicard webhook signature does not cover the payment status.** `apps/api/src/payments/multicard.service.ts:167`: sign = sha1(uuid + invoice_id + amount + secret). `status` is not signed. Anyone who sees one genuine callback (logs, a proxy, a misdirected callback) can replay it with `status=success`, and the order is marked PAID (`payments.controller.ts:125-128`). Fix (payments code, owner OK required): check the Multicard docs to confirm whether the sign really excludes status. Before setting PAID, re-fetch the invoice status from the Multicard API. Never move an order backwards from PAID on an unverified callback.

- **F7. No security headers on the API, web or admin.** There is no helmet, CSP, HSTS, `X-Frame-Options` or `frame-ancestors` (`apps/api/src/main.ts`, `apps/web/next.config.ts`, `apps/admin/next.config.ts`). The admin panel can be framed (clickjacking). Fix: `helmet()` in the API. `headers()` in both Next configs with CSP, `frame-ancestors 'none'`, HSTS, `nosniff` and `Referrer-Policy`.

- **F8. Admin sessions cannot be revoked.** `apps/api/src/common/guards/admin-auth.guard.ts:21-64`: the session is a stateless HMAC token valid for 24h. Logout (`admin-auth.controller.ts:50-54`) only clears the cookie, and a password change or reset does not invalidate existing tokens. A stolen admin cookie stays valid for 24h even after "logout" or a password reset. Fix (schema change, owner OK): add `Staff.sessionVersion`, include it in the token, and increment it on logout, password change, reset and deactivation.

## Low

- **F9.** Only staff management checks role (`admin-staff.service.ts:42,109,140`). MANAGER can change business settings, SMS templates and delivery zones, read all customers, and delete products. Decide what MANAGER and ADMIN may do, then add a roles guard.
- **F10.** Swagger UI and the full API schema are public in production at `/api/docs` (`apps/api/src/main.ts:36`). Disable it when `NODE_ENV=production`, or protect it.
- **F11.** Public pagination has no cap (`apps/api/src/products/products.controller.ts:38`, also reviews `:96`, `orders.controller.ts:94`, `admin-customers.service.ts:10`). `?limit=1000000` dumps everything, and `page=0`/a negative limit gives a 500. Clamp to 1..100.
- **F12.** Admin image upload has no size limit and trusts the client MIME type (`admin-upload.controller.ts:22`, `admin-upload.service.ts:27`). Set `FileInterceptor('file', { limits: { fileSize: 10MB } })` and check magic bytes. Only staff can reach it.
- **F13.** `images.remotePatterns: hostname '**'` in both Next configs makes `/_next/image` an open image proxy (bandwidth/CPU abuse). Restrict it to the UploadThing hosts (`*.ufs.sh`, `utfs.io`).
- **F14.** The site-gate code check `apps/web/src/app/api/access/route.ts` has no rate limit, so the access code can be brute-forced (it only protects the coming-soon gate).
- **F15.** The admin password minimum is 6 characters (`admin-auth.service.ts:140,222`). Raise it to 10+.
- **F16.** Logs and error messages: staff phone numbers are logged (`admin-auth.service.ts:155,162,175`), mock SMS mode prints OTP codes to stdout (`sms.service.ts:65`, so confirm `SMS_PROVIDER` is not `mock` in prod), and Multicard error details are returned to the client (`multicard.service.ts:154`, payments code).
- **F17.** Customer login and admin reset share one OTP table keyed by phone (`otp.service.ts`). A reset code for a staff phone also works as a customer login code and the reverse. Add a `purpose` field.
- **F18.** Rate-limit counters and admin reset tokens live in process memory (`rate-limit.service.ts`, `admin-auth.service.ts:27`). They reset on every deploy and are not shared if the API is scaled to more than one replica.
- **F19.** Review and return `photos` accept any strings, unvalidated (`reviews.service.ts:46`, `returns.service.ts:68`). Validate them as https URLs on the UploadThing host and cap the count.

## Checked, nothing found
Ownership/IDOR on orders, returns, extensions, reviews, addresses, favorites and payment checkout is correct. Every `admin/*` controller has `AdminAuthGuard`. There is no raw SQL, `$queryRawUnsafe`, exec or eval. The only `dangerouslySetInnerHTML` is a static theme script. Git history holds no `.env`, dumps or keys (only `.env.example` files with placeholders), and the code has no hard-coded tokens. The only public env var is `NEXT_PUBLIC_API_URL`. OTPs use `crypto.randomInt` with a timing-safe compare and 3 attempts. Customer session tokens are 32 random bytes, 30 days. Admin passwords use bcrypt cost 12. The admin cookie is HttpOnly, Secure in prod and Lax. The webhook checks amount and uuid against the order. Account deletion anonymizes and revokes sessions. Next is 15.5.14 (the middleware-bypass CVE is patched).
