# RentEvent storefront — UI/UX tech spec

**Date:** 2026-09-16 · **Scope:** `apps/web` (rentevent.uz, behind the preview gate) · **Method:** walked the live production site at 1440×900 and 375×812 (light + dark), read the API payloads the pages actually receive, and read the source for every screen touched. Lens: minimalism + "juice" (Apple-grade restraint with tactile feedback), and Krug's *Don't Make Me Think* — every screen must answer *what is this, what can I do here, where do I go next* without reading.

**Reference the client likes:** fair.rent — dense, photographic, one loud CTA, categories as picture tiles, fairs on the front page.

## 2. Design principles to hold the line on

1. **One loud colour per screen.** Orange is the hero and the primary button. Nothing else on the page may be orange except icon chips ≤ 48 px. If two things are orange on one screen, one of them is wrong.
2. **Paper, not white.** Background `#fbfaf7`, cards `#fff`, borders `#ebe7e0`. Keep it — it's why the grey studio photos look warm.
3. **Graphite for the ending.** The closing CTA band and set cards are `#171717`. That is the only dark surface on a light page.
4. **Content first, motion second.** Nothing above the fold starts invisible. Motion is ≤ 450 ms, transform-only, once, and respects `prefers-reduced-motion`.
5. **Every card is one link.** No "Подробнее" buttons inside a card that is already a link (Krug: needless choice).
6. **Facts, not adjectives.** "41 позиций", "от 500 000 сум", "48 ч" — never "широкий выбор", "лучшие цены".
7. **Minimum tap target 40 px, minimum body text 14 px, minimum label 12 px.** The header currently breaks all three.

## 3. Site-wide findings

### 3.1 Motion (P1 — hurts every page)
- **Symptom:** every route (`/catalog`, `/sets`, `/events`, product page) mounts with `initial={{ opacity: 0 }}` on the title and grid; `whileInView … margin: '-60px'` on rails. Screenshot of `/catalog` 3 s after load: title at 20 % opacity, grid blank. On a fast scroll on `/` the "Условия" grid was fully blank until the observer caught up.
- **Fix:** replace ad-hoc `motion.div` wrappers with `components/home/Reveal.tsx` (already written): `amount: 0.15`, no negative margin, 450 ms. Never animate `opacity` from 0 on the H1 or the first row of content. Wrap all reveals in `useReducedMotion()` → render static.
- **Files:** `app/catalog/page.tsx`, `app/sets/page.tsx`, `app/events/page.tsx`, `app/product/[id]/page.tsx`, `components/home/ProductRail.tsx`, `components/catalog/CategoryCard.tsx`, `components/ui/Card.tsx` (`animate` prop).

### 3.2 API ↔ type drift (P1 — silent data loss)
- `GET /categories` returns `{ id, name, imageUrl, iconName, displayOrder, productCount, children }`. Shared `ICategory` promises `_count.products`, `parentCategoryId`, `isActive`. Result: product counts never rendered in `CategoryCard` or the catalog chips; `parentCategoryId` filter is a no-op.
- `GET /products` items carry `category: { id, name }` and no `categoryId`, but `IProduct.categoryId` is typed required.
- **Fix (pick one, do it in the API):** make `apps/api` categories controller return `_count: { products }`, `parentCategoryId`, `isActive`, and products return `categoryId` alongside `category`. Then delete the `productCount ?? _count` shim in `app/page.tsx`. Add a contract test (there is a pattern in `apps/api` date-filter tests).

### 3.3 Header (P1)
Measured on prod at 1440: nav labels 11 px uppercase; search input 11 px with a 1 px hairline; phone/mail row 10 px; language/theme tab 10 px. Fair.rent: nav 14 px, search 13 px, icons 20 px.
- Nav 11 → 13 px, letter-spacing 0.08 em (keep uppercase). Search input 11 → 14 px, height 36 px, visible border on focus. Phone/mail row 10 → 12 px.
- Language switch: keep, but 12 px and 32 px tall. **Drop the theme toggle** from the header (system preference only) — a rental shop does not need a manual dark mode; it's one more control to think about and one more surface to QA. Keep the CSS.
- The red **"Арендовать" side tab overlaps content** (cart summary card at 1440, product page price box). Options in order of preference: (a) show it only after the hero scrolls out and hide on `/cart`, `/checkout`, `/product/*`; (b) reserve a 40 px right gutter on `xl`.
- `<title>` is English ("RentEvent - Event Equipment Rental") on the RU default. Use `generateMetadata` per locale or at least RU by default.

### 3.4 Mobile navigation (P1)
Mobile header = logo · user · cart · burger. No search, no catalog, no phone. The product is the catalog; the burger hides it.
- Add a **bottom tab bar** on `< md`: Каталог · Поиск · Корзина · Профиль (4 items, 56 px, safe-area padded). The fixed side tab is already hidden on mobile, so this becomes the persistent CTA.
- Or, minimum: search icon in the header that expands a full-width field, and "Каталог" as the first burger item in bold.

### 3.5 Product card (P2)
- Remove the "Подробнее ↗" pill — the card is a link. Replace with a quiet arrow on hover only (desktop).
- "В ДЕНЬ" eyebrow above the price is mono, uppercase, letter-spaced → reads like metadata. Use one line: **300 000 сум** / день.
- "Осталось 1" amber-on-white badge ≈ 2.6:1 contrast. Use `bg-amber-100 text-amber-900` or the graphite pill from the hero.
- Names like "Барный стул   Белый " (3 spaces) and "Стелаж" (typo) come from the DB — see §4.

### 3.6 Catalog (P2)
- Default sort "Сначала новые" → "По популярности" (rental shoppers want the proven items first; "new" means nothing to them).
- The **date filter is the differentiator** and it's a small grey input under the chips. Make it a bar: "На какие даты?" with the picker, pre-filled from `rental-period-store`, and echo "Показано только свободное 16–18 сент." above the grid when set.
- Category chip row: "прочий" (lowercase) → rename "Прочее" in the DB; chip overflow at 1440 relies on the edge fade — add a small "›" hint.
- List/grid toggle: nobody uses list view on a 41-item catalog. Remove.

### 3.7 Product page (P2)
- Good bones (breadcrumb, gallery, price box, dates, quantity, one orange CTA). Two additions: "Свободно N шт. на выбранные даты" directly under the date field (the API already returns `availableStock`), and move the description above the fold on desktop (it renders under the CTA today).
- "Похожие товары" shows 3 cards in a 4-column grid — fill 4 or drop to 3 columns.

### 3.8 Cart / checkout (P1 for the copy bug)
- `stores/cart-store.ts` hard-codes `deliveryFee: 0`; the cart prints "Доставка: Бесплатно" and "Доставка по Ташкенту бесплатно" on a 250 000 сум order, while `/delivery` and FAQ say free **from 500 000 сум**. Either implement the threshold in the store (and show "до бесплатной доставки осталось X") or change the FAQ/delivery copy. Decide with the client; the threshold version is the better UX.
- The summary card appears ~1 s after the items (client-only hydration) → layout jump. Render a skeleton card immediately.

### 3.9 Sets & events (P2)
- Events copy promises "Выберите событие, для которого арендуете оборудование — мы подготовим всё под площадку", but the whole card opens the fair's external website in a new tab. Make the card a **"Арендовать для этой выставки"** action: set `rental-period-store` to the event dates and open `/catalog`; keep the external site as a small secondary link.
- Sets: the modal date prompt is right. Set photos are product collages on grey — commission one real photo per set (3 sets — cheap).

### 3.10 Footer (P2)
- Placeholder links: `https://instagram.com`, `https://facebook.com` (`components/layout/Footer.tsx:56,67`). Point to real profiles or remove the icons — a dead social icon reads as an abandoned site.
- Address "г. Ташкент, ул. Амир Темур, 1" and phone fallback `+998 90 123 45 67` are placeholders in code (`home`, `Footer`, `settings` fallback). Confirm real values are in Business Settings and delete the fallbacks.
- The full-width "Компания" tagline block above the footer repeats the H1. Replace with the Telegram/phone strip or drop it (~300 px of nothing on every page).

### 3.11 Coming-soon gate (P3)
- Works. Language pills top-right are fine. Add `autoFocus` on the code input, and the RU copy "Мы готовим что-то особенное" → "Сайт открывается по коду раннего доступа" (say what the field is for).

### 3.12 Accessibility & performance (P2)
- Orange text on white uses `--color-primary-text` (#CF4A25, 4.5:1) — keep doing that; the amber badge (3.5) and `text-white/70` on graphite (4.3:1) need a nudge.
- All product images are `<img>` from ufs.sh at original size (~200–600 KB each). Add `width/height` (aspect boxes exist, so CLS is OK) and route through `next/image` with `sizes` — remote pattern `**` is already allowed in `next.config.ts`.
- Focus rings: buttons have none visible on keyboard focus. Add `focus-visible:ring-2 ring-primary/50 ring-offset-2` to `Button`, links in `Header`.

## 6. Making the UI "prompt-reachable" — component library plan

**Goal:** a non-designer can type *"add a Dialog that asks for rental dates, use our Button and Calendar"* into ChatGPT/Claude/v0 and get code that drops in and already looks like RentEvent.

**Recommendation: shadcn/ui** (MIT, copy-paste components on Radix primitives, Tailwind v4-ready). It is the component vocabulary every LLM knows best — prompts like "shadcn Sheet", "shadcn Command palette" produce correct code first try. Alternatives considered: Mantine/Chakra (runtime CSS-in-JS, fight Tailwind), HeroUI (heavier, own theme system), Radix Themes (good, less LLM-familiar). Add **Magic UI** or **Aceternity** (also copy-paste, same stack) only for individual "juice" pieces — marquee, shimmer button, number ticker.

**Steps (≈1–2 days):**
1. `npx shadcn@latest init` in `apps/web` with the Tailwind v4 preset → generates `components/ui/*` and `lib/utils.ts#cn` (already exists — keep ours).
2. Map tokens: shadcn reads `--background`, `--foreground`, `--primary`, `--card`, `--border`, `--radius`. The site already defines `--color-*` in `@theme`; add the shadcn aliases in `globals.css` (`--primary: var(--color-brand-orange)` …). One file, no visual change.
3. Replace, one by one, with the shadcn version while keeping our look: `Button` (override `buttonVariants` to the pill + orange glow), `Dialog` (replaces `Modal.tsx` + Headless UI — drop `@headlessui/react`), `Select`, `Input`, `Badge`, `Skeleton`, `Sheet` (mobile menu + cart drawer), `Tabs`, `Tooltip`, `Command` (header search with suggestions), `Calendar` (wraps react-day-picker, already a dependency).
4. Commit a **`apps/web/DESIGN.md`** — tokens (§5), principles (§2), the component list with one usage snippet each, and a prompt preamble:
   > "This project uses Next 15 App Router, Tailwind v4, shadcn/ui, framer-motion. Colours: brand orange #F2562B on paper #fbfaf7, graphite #171717 for dark bands. Buttons are pills. Use `@/components/ui/*`. No new colours, no gradients except the hero. Sections use `SectionHeader` and `Reveal` from `@/components/home`."
   Pasting that at the top of any prompt is what makes the output land in-style.
5. Storybook is overkill; instead add `/dev/ui` (guarded by `NODE_ENV`) that renders every component in every state — the page a prompt-author looks at to know what exists.
